# בדיקת יציבות דף הבית במובייל

## עדכון בעקבות הקלטת האייפון

בהמשך לדיווח על קפיצה בזמן גרירת הסליידר, סליידר הזמן בהדגמת דף הבית מושבת באייפון גם במצב אופקי. הוא שומר על מראהו, אינו מקבל פוקוס ואינו מגיב ללחיצה, לגרירה או למקלדת; מחווה שמתחילה מעליו עדיין מאפשרת גלילת עמוד. ההשבתה מוגבלת להדגמה, והסליידר בעורך הסרטונים נשאר פעיל. הבדיקות מכסות מגע, גרירה ומקלדת ב־Chromium וב־WebKit, וגלילת מגע דרך CDP ב־Chromium.

בהקלטה מ־11.10.2026 בשעה 21:51 שורת היתרונות משנה שבירת שורות והדגמת הטלפון קופצת בגובה. ההקלטה מראה שהבדיקות הקודמות לא הספיקו לאימות במכשיר.

באייפון בלבד, גם ב־Safari וגם ב־Chrome, בוטלו הניגון האוטומטי של ההדגמה והגלריה, מעברי CSS, הבהוב/תנועת קישוטים, תנועת hover וגלילה חלקה יזומה. בחירת סגנון אינה מתחילה ניגון. לחיצה מפורשת על ״צפו בדוגמה״ או על ההדגמה עדיין מאפשרת ניגון והשהיה. הצבעים, הטיפוגרפיה, התמונות, המסגרות והפריסה לא הוחלפו. העורך עצמו אינו מושפע.

`tests/marketing-iphone-motion.spec.ts` בודק משתמש מחובר כמו בהקלטה, ללא הפעלת reduced-motion במערכת: שעונים עצורים, גלריה סטטית, היעדר אנימציות CSS, יציבות שורת היתרונות וההדגמה, סיבוב מסך, החלת סגנון וניגון ידני. יש גם בדיקת ביקורת ל־Android. עדיין נדרש לאמת באותו מכשיר שהקפיצות נעלמו; אין טענה לוודאות על סמך אמולציה.

התיקון מ־11.10.2026 משחזר את בידוד שעון ההדגמה, גלילת הקרוסלות וגלילת המגע שתוקנו ב־`560ccb0` ואבדו בהמשך. הבדיקה לפני התיקון מצאה 49 רינדורים של דף הבית בזמן ניגון קצר, במקום לכל היותר שניים. זו ראיה לנסיגת הקוד, לא שחזור של ריצוד GPU באייפון אמיתי.

בנוסף, ההדגמות והאנימציות מושהות בזמן גלילת העמוד ומתחדשות אחרי 180ms ללא גלילה, תוך שמירת בחירת המשתמש להשהות ניגון. בטלפונים, כולל מצב אופקי, רקעים סטטיים מחליפים שכבות טשטוש נעות, וסרגל הפעולות אינו משתמש בטשטוש או במעבר מונפש. טעינת ההתחברות אינה מסירה את דף הבית.

## בדיקות מהמחשב

```powershell
npx playwright install chromium webkit
npm run test:marketing
node scripts/verify-marketing-qa.mjs
```

הפקודה הראשונה מתקינה דפדפני בדיקה. השנייה מפעילה בדיקות frontend מקומיות עם שירותים מדומים, ללא שרת אפליקציה או מסד נתונים. היא מכסה Chromium ו־WebKit בתצורת iPhone: גלילה חוזרת, שינוי גובה חלון, קרוסלות, מצב אופקי, השהיה וחידוש ניגון, התחברות והתאמה לגדלי מסך. הזרקת מחוות מגע אמיתיות ב־CDP זמינה רק בשלוש בדיקות Chromium; הן מדולגות במפורש ב־WebKit.

הפקודה השלישית בודקת את הבנייה המפורסמת ב־QA, כאורח וללא שינוי נתוני משתמש, ושומרת צילומים ב־`tmp/marketing-scroll-qa`. יש להריצה רק לאחר עדכון ה־QA הקיים לפי `AGENTS.md`. אין צורך ליצור סביבת שרת נוספת.

## אימות Safari אמיתי ללא אייפון בבעלותך

אפשר לפתוח [BrowserStack Live](https://www.browserstack.com/live) מהמחשב ולבחור **אייפון אמיתי** עם Safari. נדרשת גישה לשירות. [הוראות השירות](https://www.browserstack.com/docs/live/get-started/test-websites).

1. לפתוח `https://quick-caption.com/qa/` ולבצע טעינה מחדש.
2. לגלול לאט ומהר בין הכותרת, ההדגמה, הסגנונות והתחתית, לפחות עשר פעמים בשני הכיוונים.
3. להתחיל מחוות גם מעל תמונת ההדגמה ופס הזמן. לבדוק קרוסלות דרך החלקה ונקודות ניווט.
4. לבדוק כאשר סרגל הכתובת של Safari מתכווץ ומתרחב, ובמצב אנכי ואופקי.
5. להשהות את ההדגמה, לגלול ולוודא שאינה מתחילה מעצמה. להפעיל אותה ולוודא שהיא ממשיכה אחרי סיום הגלילה.
6. לבדוק שוב אחרי מעבר ללשונית אחרת וחזרה, ואם אפשר גם לאחר התחברות. לרשום דגם, גרסת iOS ולהקליט מסך אם נותר ריצוד.

להשלמת האימות יש לבדוק על שני דגמי אייפון/גרסאות iOS, לרבות הדגם שבו דווחה התקלה אם ידוע. [Playwright WebKit](https://playwright.dev/docs/browsers#webkit) בודק את מנוע הדפדפן במחשב; הוא אינו Safari על חומרת iPhone. גם שינוי גובה החלון בבדיקה אינו מחקה את ממשק Safari או את ה־GPU. בדיקות אוטומטיות שעברו אינן הוכחה שהריצוד במכשיר נעלם.
